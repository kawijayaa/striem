# Full KQL implementation

## Objective and completion standard

Implement all of the Microsoft KQL specification robustly with no bugs. This objective remains **incomplete**. No subset of operators, passing test suite, or syntax-only recognition establishes completion.

For each construct, evidence must cover syntax, binding/type inference, execution semantics (including nulls and invalid inputs), output schema/types, errors, and integration with Striem. Operator combinations, parameterized expressions, and boundary cases must be exercised. Documented approximation is not proof of exact Kusto compatibility.

## Authoritative inventory

The companion KSQL checkout has a feature ledger covering more than 650 entries. Its pinned Microsoft source is recorded in `third_party/ksql/inventory/source.json`. The pinned catalog includes 397 scalar functions, 24 conversion entries, 61 aggregates, 8 window entries, and 47 plugins, plus operators, sources, statements, and scalar operators. Registry entries can overlap.

`features.All()` and `features.JSON()` expose the baseline. The ledger distinguishes inventory, recognition, translation, and semantics. It is a starting inventory, **not evidence that everything marked equivalent has complete Kusto behavior**, and must be reconciled against the current Microsoft language/reference as implementation proceeds. Newer features remain in scope.

## Current integration

- The source of compiler development is the companion `ksql` repository.
- Striem builds against a portable snapshot in `third_party/ksql` using a module replacement. It does not depend on a developer's home-directory layout.
- `scripts/sync-ksql.py` refreshes source/tests/license/docs and records hashes and the upstream base commit. Changes in the companion checkout are included, even before release.
- SQLite runtime adapters remain in `internal/database`; application mappings and compatibility tests remain in `internal/kql`.
- The compiler's `not()` implementation now supplies Boolean metadata directly. The former application metadata-recovery workaround was removed.

## Verified implementation increments

- Default and explicit `innerunique`: one complete left row per equality-key tuple, preserved right multiplicity, internal rank-column collision avoidance, explicit/reversed side keys, composite keys, null/nonmatching keys, empty inputs, tabular bindings, and output schema.
- `rightsemi` / `rightanti`: right-only columns, retained right duplicates, null-key behavior, empty inputs, and correlated equality predicates.
- SQL window AST/renderer support with partition/order clauses and parameter traversal. This is infrastructure; it does not itself implement KQL window functions or serialization semantics.
- SQLite execution tests in the compiler and Striem; render checks for other supported SQL dialects. Render checks do not prove execution on those databases.
- Union aligns bound input schemas by name/type: outer null padding, distinct columns for conflicting types, suffix collision avoidance, inner intersection, duplicate retention, nested/standalone queries, and tabular bindings. Tests cover real event tables, Boolean expressions, empty legs, metadata, bound parameters, and projection limits.
- Union semantics reference: [Microsoft union operator](https://learn.microsoft.com/en-us/kusto/query/union-operator?view=microsoft-fabric). Unknown input schemas and unsupported options produce diagnostics. Wildcards, `withsource`, fuzzy resolution, zero-column outputs, case-distinct names on SQL backends, and exact decimal/real and guid/string distinctions remain open.

- Column-selection patterns: `project-away`, `project-keep`, and `project-reorder` accept case-sensitive `*` patterns. Reordering supports ordinal and natural numeric sorting, first-match deduplication, and retention of unspecified columns. Execution tests cover metadata, quoted literal names, ASCII numeric runs beyond integer range, missing patterns, and expansion limits. Reference: [Microsoft project-reorder](https://learn.microsoft.com/en-us/kusto/query/project-reorder-operator?view=microsoft-fabric). Unicode digit collation, zero-column results, and case-sensitive exact-name binding remain open.

- Typed function adapters expose argument types and return types, preserving metadata through projections and allowing predicate validation. Bag aggregation now implements `make_bag`, `make_bag_if`, and legacy `make_dictionary`: null/non-bag skipping, duplicate-key selection, empty objects, optional size limits, nested values, integer precision, and explicit resource errors. SQLite execution and HTTP JSON tests cover the runtime. [Reference](https://learn.microsoft.com/en-us/kusto/query/make-bag-aggregation-function?view=microsoft-fabric). Unknown types and dynamic strings extracted through SQLite JSON still need a tagged dynamic-value representation to remove all string/object ambiguity.

- Numeric conversion adapters now return null for invalid text and overflow, truncate toward zero, enforce 32/64-bit bounds, and preserve long integer text precision. Boolean conversions preserve Boolean metadata. Compiler schemas now distinguish int/long, including union suffixes and mixed arithmetic promotion. Execution tests cover boundaries and composition. Full dynamic-value casting, non-finite real behavior, typed literal validation, and differential string-format conformance remain open. [Conversion reference](https://learn.microsoft.com/en-us/kusto/query/toint-function?view=microsoft-fabric).

- Standard `getschema` returns the four documented metadata columns without scanning input rows. Tests cover transformations, empty inputs, wide schemas, parameter pruning, and pipeline composition. SQLite inline values now support valid aliases and empty tables. Unknown schema/types and `kind=csl` remain unsupported. [Reference](https://learn.microsoft.com/en-us/kusto/query/getschema-operator?view=microsoft-fabric).

- String indexing adapters now use zero-based Unicode character offsets, negative offsets from the end, and optional lengths. `strlen` counts Unicode codepoints including embedded NUL characters. Tests cover documented examples, non-ASCII text, large offsets, and argument diagnostics. [Substring reference](https://learn.microsoft.com/en-us/kusto/query/substring-function?view=microsoft-fabric). Full string null/coercion behavior and differential edge-case conformance remain open.

- Numeric variance/standard deviation families now execute with sample/population and conditional forms, null skipping, real metadata, and stable centered accumulation of large integers. Tests cover grouping, empty/singleton groups, nulls, integer extremes, and argument diagnostics. [Variance reference](https://learn.microsoft.com/en-us/kusto/query/variance-aggregation-function?view=microsoft-fabric). Non-finite inputs and accumulation overflow currently return explicit query errors. Kusto-compatible non-finite result representation, timespan statistics, and differential numerical conformance remain open.

- SQLite numeric `range` sources now execute using a lazy recursive CTE. Tests cover ascending/descending ranges, inclusive endpoints, exact long integers, real output types, scalar bindings, parameter ordering, joins/unions, and huge ranges with `take`. Bounds are evaluated once, and integer overflow and floating-point stagnation terminate recursion. Datetime/timespan ranges remain unsupported with explicit diagnostics. Zero-step ranges currently produce no rows, and floating-point stagnation truncates output; these edge semantics still require Kusto conformance and must not be treated as verified compatibility. [Range reference](https://learn.microsoft.com/en-us/kusto/query/range-operator?view=microsoft-fabric).

- Literal replacement now uses a NUL-safe runtime adapter instead of SQLite `replace`, with non-overlapping case-sensitive matching, Unicode preservation, string output metadata, argument diagnostics, with string argument validation. Expanded output above 4 MiB returns an explicit query error before allocation. Tests cover the documented example, embedded NUL lookups/replacements, composition, and the resource boundary. Empty lookups retain existing no-op behavior; full null/empty-lookup and coercion conformance remains open. [Replacement reference](https://learn.microsoft.com/en-us/kusto/query/replace-string-function?view=microsoft-fabric).

- `replace_strings` now implements ordered lookup precedence against original text, non-overlapping matches, nonstring lookup skipping, and match reservation for nonstring rewrites. Tests execute all four documented examples, Unicode/NUL matching, scalar bindings, metadata, and resource errors. Arrays, output, match count, and search work are bounded with explicit errors. Unequal arrays currently produce a query error and empty lookup entries are ignored; those edge cases, null behavior, and full dynamic coercion still need differential conformance. [Multiple replacement reference](https://learn.microsoft.com/en-us/kusto/query/replace-strings-function?view=microsoft-fabric).

- Standard JSON-compatible `dynamic(...)` constants now parse and bind as dynamic values, including arrays, nested objects, scalars, and null. Execution tests cover scalar bindings, nested access, string escapes, signed/exact long JSON values, malformed literals, metadata, and both parameter modes. JSON token validation preserves boundaries and rejects expressions rather than concatenating them into constants. Typed Kusto constants inside dynamic literals, scalar type tags, and full accessor semantics remain open. [Dynamic reference](https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/dynamic?view=microsoft-fabric).

- `tolower` and `toupper` now use Go Unicode simple case conversion instead of SQLite ASCII-only conversion, preserve embedded NUL text, validate arity, and keep string output metadata. Execution tests cover documented ASCII examples, accented Latin/Greek/Cyrillic, filtering/grouping, dynamic fields, nulls, and metadata. Exact Kusto case tables, locale/expansion rules, and tagged dynamic string coercion remain unverified and open. [Lowercase reference](https://learn.microsoft.com/en-us/kusto/query/tolower-function?view=microsoft-fabric), [uppercase reference](https://learn.microsoft.com/en-us/kusto/query/toupper-function?view=microsoft-fabric).

- String literal decoding is now shared between the compiler and application full-text prefilter. Single/double quotes decode the same escapes; verbatim/multiline forms retain backslashes; adjacent literals concatenate across whitespace/comments, including inside JSON dynamic literals. Tests cover documented concatenation examples, Unicode/surrogate pairs, NUL composition, escaped quotes, parameter modes, and rejection of malformed escapes. Escape widths and octal scanning follow the [Microsoft lexer](https://github.com/microsoft/Kusto-Query-Language/blob/master/src/Kusto.Language/Parser/TokenParser.cs). Lone surrogates currently produce diagnostics; exact malformed-input behavior, hidden-literal telemetry guarantees, and the complete string type/coercion model remain open. [String reference](https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/string?view=microsoft-fabric).

- Corrected overly restrictive argument validation introduced by string adapters: the Microsoft function catalog declares scalar arguments for case conversion and `substring`, and string/dynamic arguments for `strlen`. A shared typed scalar formatter now accepts numeric input, preserves exact long text, and formats typed Booleans by name rather than SQLite integer storage. Tests cover literal/column/pipeline input and dynamic numeric/string fields. Exact real formatting, datetime/timespan text, non-finite conversions, and tagged dynamic coercion remain open. [Microsoft function catalog](https://github.com/microsoft/Kusto-Query-Language/blob/master/src/Kusto.Language/Functions.cs).

- `indexof` now executes scalar text searches with Unicode character positions, optional relative starts/lengths/occurrences, exact long input conversion, long output metadata, generated unnamed result columns, and bounds clamping without integer overflow. Repeated occurrence searches use linear-time KMP matching with a bounded failure table. Integration tests execute all nine documented examples and cover NULs, scalar bindings, filtering, and diagnostics. Zero occurrence currently returns an explicit query error; empty matches and overlapping occurrences have characterization tests but remain unverified against Kusto. Occurrence validation currently accepts literal/scalar-let integer constants; general constant expression folding, dynamic type coercion, and complete null/edge semantics remain open. Length windows advance after matches to satisfy the documented repeated-occurrence example; this interpretation still needs engine-level differential verification. [Index reference](https://learn.microsoft.com/en-us/kusto/query/indexof-function?view=microsoft-fabric).

- Regex replacement now supports `replace_regex(source, regex, rewrite)` and corrects the legacy `replace(regex, rewrite, source)` signature previously mapped incorrectly to literal replacement. Numbered `\0`/`\1` captures use KQL rewrite syntax while dollar signs remain literal; matches do not overlap. Tests cover the documented substitution, Unicode/NULs, multiline flags, optional groups, aliases, metadata, and explicit resource errors. Pattern/rewrite literal or scalar-let constants are validated; input/output sizes, capture offsets, match count, and expansion work are bounded. Full Kusto regex syntax, empty-match behavior, escaped rewrite edge cases, unavailable group semantics, and general constant expression folding remain open. [Regex replacement reference](https://learn.microsoft.com/en-us/kusto/query/replace-regex-function?view=microsoft-fabric), [legacy signature](https://github.com/microsoft/Kusto-Query-Language/blob/master/src/Kusto.Language/Functions.cs).

## Remaining workstreams (all stay in scope)

1. **Scalar semantics and types:** complete function catalog, Unicode/string behavior, all casts and null-on-failure behavior, dynamic values/literals, GUID/decimal/timespan types, scalar `let`/function definitions, datetime arithmetic, formatting/timezones, Boolean and null semantics.
2. **Aggregates:** full aggregate catalog; `arg_min`/`arg_max` row selection; conditional/dynamic collections; percentiles/statistics; genuine HLL-based approximate counts and mergeable states; ordering/default/empty-input behavior.
3. **Relational operators:** remaining union forms and complete scalar type distinctions, remaining projection forms, parse variants, multi-array expansion, aggregating `mv-apply`, partition/scan, top-nested/top-hitters, series operators, find/search variants, schema operators, and all hints/parameters with their defined semantics.
4. **Ordering and windows:** serialized row identity/order through pipelines; row_number/rank/cumulative/neighbor/session functions and restart predicates.
5. **Sources, statements, and reusable queries:** all source forms; parameter declarations; functions/invoke; external data; database/cluster/table resolution; entity groups, macro expansion, materialization, session controls.
6. **Graphs and specialized scalar families:** graph construction/matching/path algorithms, geospatial/S2/H3 operations, series analysis, encodings/hashes, network functions, regex compatibility.
7. **Plugins and execution services:** evaluate plugins, their declared output schemas, and any required external runtimes/services. Unavailable services must not be silently replaced with invented results.
8. **Product integration:** completion/highlighting, API contracts, render directives/chart presentation, query diagnostics/cancellation/limits, browser execution, deployment and migration support.
9. **Conformance:** official documented examples, operator composition, differential fixtures against Kusto where available, adversarial/resource cases, platform coverage, current-catalog reconciliation, and a requirement-by-requirement completion audit.

Known existing semantic differences remain open: exact bounded `dcount` differs from Kusto approximation; `take_any` currently maps to a minimum; some SQLite conversions and string indexing differ from KQL; chronology/serialization and dynamic output metadata need broader review. Existing behavior must be corrected as part of full support, rather than declared sufficient.
