# Full KQL implementation

## Objective and completion standard

Implement all of the Microsoft KQL specification robustly with no bugs. This objective remains **incomplete**. No subset of operators, passing test suite, or syntax-only recognition establishes completion.

For each construct, evidence must cover syntax, binding/type inference, execution semantics (including nulls and invalid inputs), output schema/types, errors, and integration with Striem. Operator combinations, parameterized expressions, and boundary cases must be exercised. Documented approximation is not proof of exact Kusto compatibility.

## Authoritative inventory

The companion KSQL checkout has a feature ledger covering more than 650 entries. Its pinned Microsoft source is recorded in `../ksql/inventory/source.json`. The pinned catalog includes 397 scalar functions, 24 conversion entries, 61 aggregates, 8 window entries, and 47 plugins, plus operators, sources, statements, and scalar operators. Registry entries can overlap.

`features.All()` and `features.JSON()` expose the baseline. The ledger distinguishes inventory, recognition, translation, and semantics. It is a starting inventory, **not evidence that everything marked equivalent has complete Kusto behavior**, and must be reconciled against the current Microsoft language/reference as implementation proceeds. Newer features remain in scope.

## Current integration

CI pins the KSQL commit that includes query parameters, the parse operators and window functions.
That commit is local to the companion checkout until it is published; remote CI
cannot fetch it before then. Constant-only adapter arguments, such as
`extract_all` patterns, still require compiler metadata to recognize bound
parameters as constants.

- The source of compiler development is the companion `ksql` repository.
- Striem resolves its compiler module directly from the independent sibling checkout at `../ksql`. No compiler snapshot or synchronization script is kept in this repository.
- Docker receives that checkout through `--build-context ksql=../ksql`; CI checks out an explicit KSQL commit separately. Compiler changes must be published there before remote CI can fetch them.
- SQLite runtime adapters remain in `internal/database`; application mappings and compatibility tests remain in `internal/kql`.
- The compiler's `not()` implementation now supplies Boolean metadata directly. The former application metadata-recovery workaround was removed.

## Verified implementation increments

- Added `make-series` (KSQL `docs/make-series.md`): bin-aligned arrays with defaults, `from`/`to`/`step`, `by` groups, per-series bounds when `from`/`to` are omitted, `kind=nonempty` and the `in range()` form. Microsoft's examples pass, including the `mv-expand` fill example. Also accepts `string(null)`. `series_*` analysis functions remain open.

- Added `union withsource=Column` (table names, or `union_argN` for expressions), multi-column `mv-expand` in lockstep with null padding and Microsoft's bag-into-single-property expansion, and raised the expansion limit from 1 to 16 columns. Datetime-literal normalization now also reaches `in` subqueries and expansion arrays.

- Added `rand`, `bin_at` (numbers, timespans and datetimes aligned to a fixed point) and `array_sort_asc`/`array_sort_desc` with Kusto's mixed-type ordering, `nulls_last` and companion arrays; Microsoft's examples pass. With several arrays the result is one dynamic array of arrays (supporting `array_sort_asc(a, b)[1]`) rather than Kusto's per-array output columns.
- Scope for CTF log forensics: the geospatial functions (S2, H3, geohash, geo lookups and overlays), the `series_*` analytics family, unit conversions (`convert_*`), `format_bytes`, the beta distribution and the covariance aggregates were removed; they report unsupported-function errors. This also drops the `golang/geo` and cgo `h3-go` dependencies. `make-series`, percentiles and sketches remain.
- `tostring` and `strcat` print reals with Kusto's shortest round-trip digits and E notation (`1E+15`) through KSQL's `ScalarText` capability, instead of SQLite's 17-digit cast.
- Added `string_size`, `base64_encode_fromguid`/`base64_decode_toguid` (.NET Guid byte order, which round-trips; Microsoft's decode example swaps one group), `new_guid`, and `datetime_utc_to_local`/`datetime_local_to_utc` with the embedded IANA zone database. `parse_version` remains open because Striem has no decimal type.
- Added `percentile`, `percentiles` (one column per percentile, Kusto's names or tuple names), `percentiles_array` and the weighted `percentilew`/`percentilesw`/`percentilesw_array` over numbers, datetimes and timespans, using a merging t-digest that keeps up to 4096 values exactly (so small groups give exact nearest-rank results) and compresses beyond that; `tdigest`, `tdigest_merge`/`merge_tdigest`, `percentile_tdigest`, `percentiles_array_tdigest`, `rank_tdigest` and `percentrank_tdigest`; and HyperLogLog `hll`, `hll_if`, `hll_merge` and `dcount_hll` with Kusto's accuracy levels 0-4 (exact up to 4096 distinct values). Sketches are Striem-specific JSON, not Kusto's binary layout; `percentile_tdigest` without `typeof(T)` returns dynamic.
- `partition` (legacy, native and shuffle, including the legacy `{ ... }` form with its own source) runs its subquery per key; the API discovers the keys with a 2-second query, and Kusto's 64-key legacy limit applies (1024 for native/shuffle).
- Added `has_ipv4`, `has_ipv4_prefix`, `has_any_ipv4` and `has_any_ipv4_prefix` (addresses bounded by non-alphanumeric characters), and `range()` over datetimes or timespans with a timespan step. KSQL now accepts hex literals, typed constants inside `dynamic(...)`, bracket-quoted `as` names, `column_names_of(F())`, `count(x)` and long arguments for int parameters.
- `make_list`, `make_set`, `make_list_if`, `make_set_if`, `make_list_with_nulls` and the deprecated `makelist`/`makeset` use one collector: nulls are skipped (except with nulls), the optional maximum size is honored, and elements of dynamic arrays are added individually, as Microsoft's examples show (`make_list(pack_array(x))` keeps arrays nested). `buildschema` merges dynamic values into Kusto's schema form (types in first-seen order, nested objects, `` `indexer` `` for arrays), bounded to 65536 schema nodes. `mv-apply` subqueries may now use `summarize`, `count`, `distinct`, `take` and `top`, evaluated per input row.
- `set` statements: `query_take_max_records`/`truncationmaxrecords` limit results, `query_now` fixes `now()` and `ago()`, and `query_bin_auto_size`/`query_bin_auto_at` define `bin_auto`; other options are accepted with a warning. `alias database`, `cluster()` and `database()` remain errors, since Striem has one database and must not silently query it in their place.
- `declare pattern` statements (KSQL) map string arguments and paths to queries; missing references report Kusto's `pattern references were not declared` error.
- `scan` (KSQL `docs/scan.md`) runs Kusto's sequence matching (declared columns, step references, `with_match_id`, `output=all|last|none`) as a recursive query, about 5 µs per input record; Microsoft's cumulative-sum, fill-forward, session and Start/Stop sequence examples pass. `row_window_session` (in `extend`) and `evaluate rows_near(...)` build on it. `top-nested` (without `with others`) and exact `top-hitters` are supported. `reduce` (both kinds, with `threshold` and `characters`) clusters values with Vaarandi's SLCT through the `kql_reduce`/`kql_reduce_source` aggregates. Input is capped at 262,144 distinct values or 64 MB, and values with more than 256 terms are treated as a single term. `evaluate sequence_detect(...)` returns every chain of step records within the step and span windows, correlated by dimensions; Microsoft's StormEvents output is reproduced on its matching records. Dense matches over wide windows multiply, and the API's row and byte caps bound them.
- Added forensic text helpers: `hash` (xxhash64 over Kusto's byte forms; Microsoft's string, modulo and datetime values match) and `hash_many` (comparable within a query, as Kusto documents), `parse_command_line` (CommandLineToArgvW rules), `parse_path` (drive, UNC, POSIX, `file://` and alternate data streams), `regex_quote`, `indexof_regex`, `has_any_index`, `extract_json`/`extractjson` (JSONPath `$`, `.name`, `['name']`, `[index]`), `dynamic_to_json` (sorted keys) and `around`.
- `evaluate narrow()`, `evaluate pivot(...)` (pivot values discovered with a 2-second query, or taken from an output schema) and `evaluate ipv4_lookup/ipv6_lookup(...)` (CIDR matching, extra keys, `return_unmatched`).
- `search` follows Kusto's predicate syntax (`*` placement selects has/hasprefix/hassuffix/contains/regex, `Column:"term"`, `*`, `kind=case_sensitive`), and a search that starts a query (`search "x"`, `search in (T1, A*) "x"`) spans every dataset table, or the matching ones, with a `$table` column; the combined `Events` view is not searched twice, and `let V = view () {...}` views are included. `find` (withsource, `in (...)`, `project-smart`, `project` with types and `pack_all()`) runs over the same tables with per-table `pack_` bags, and `pack_all([ignore_null_empty])` packs a row's columns. `has` accepts punctuation terms such as IP addresses. `project-by-names` and `column_names_of()` take compile-time constant names, arrays and patterns.

- Added `evaluate bag_unpack` (KSQL `docs/bag-unpack.md`) with output schemas, prefixes, `columnsConflict`, `ignoredProperties`, and data-driven slots: without a schema, Striem runs a bounded key-discovery query (2-second deadline) before compiling. Microsoft's examples pass. Raised the per-operator projection limit from 32 to 256 columns, since unpacked bags and wide event schemas exceeded it. Query hints, `in (subquery)`, `let ... = view () {...}` and `union isfuzzy=true` are supported.

- Security: `table("...")`, `external_table("...")` and `materialized_view("...")` had compiled to raw SQL table references, bypassing the table catalog and dataset filters, so `table("sqlite_master")`, `table("investigation_progress")` or `table("workspace_metadata")` could read storage and challenge state. They now resolve exactly like bare table names. Database/cluster qualifiers, union wildcards, management commands and SQL-like string payloads were also probed and stay rejected or parameterized.

- Ran Microsoft's documented examples (from the MicrosoftDocs/dataexplorer-docs query reference) against Striem and fixed the discrepancies found: Boolean and dynamic result types for `isnull`, `isempty`, `notnull`, `notempty`, `bag_has_key`, `bag_keys`, `ipv4_is_private` and `ipv4_is_in_range` (the API had returned `1` and JSON text); `make_list` of dynamic values (objects had been collected as escaped strings); timespans in `pack_array`, `bag_pack`, `strcat_delim`, `strrep` and `reverse`; unpadded ISO dates (`1970-5-12`), the comma form `datetime(2025, 6, 14)` and `MM-dd-yyyy`; lenient `toguid` hyphenation; and case-sensitive `let` resolution (`Region == region` had compared the column with itself). Remaining documented differences include NaN/infinity (unrepresentable in SQLite) and documentation errors such as `variancepif` showing sample variance.

- Added `format_datetime`, `format_timespan` and `make_timespan` with every documented specifier and Microsoft's examples, `range` over datetimes and timespans (KSQL), and Kusto's default result names: `sum(a)` is `sum_a`, `make_list(a)` is `list_a`, `bin(t, 1h)` is `t`, and unnamed scalar calls are `ColumnN`, from the pinned Kusto.Language `ResultNameKind` metadata. `project` now infers the same names, suffixing collisions (`strlen_s1`).

- Fixed SQL math functions failing with "no such function": this SQLite build has no math extension, so Striem now implements `sqrt`, `pow`, `exp`, `ln`, `log10`, `floor`, `ceiling`, `sign` and the trigonometric functions, with nonfinite or out-of-domain results as null. `log` is the natural logarithm (KSQL had emitted base-10 SQL `log`). `floor(value, roundTo)` is the documented alias of `bin`. `tostring(bool)` returns `true`/`false`, `strcat` converts null arguments to empty strings, and `in`/`!in`/`in~`/`!in~` expand dynamic array members.

- Fixed timespans and datetime arithmetic. Timespan literals (`1d`, `2h + 30m`, `datetime + 1d`) produced SQL INTERVAL text SQLite could not parse, and `datetime - datetime` silently subtracted text to 0. KSQL now types timespans as 100ns ticks with Kusto's operator overloads; Striem supplies datetime add/diff UDFs, typed `now()`/`now(offset)`/`ago()`/`bin()`, `totimespan`/`totime`, `dayofweek`, and API formatting as `[-][d.]hh:mm:ss[.fffffff]`. `typeof(T)` is now a type literal, so `extract(..., typeof(real))` converts captures as documented.
- Fixed `contains_cs`, `startswith_cs` and `endswith_cs`, which were case-insensitive through SQLite `LIKE`, and LIKE wildcard leakage, where `contains "_"` matched every string. `round` now follows the documented half-away-from-zero results, including negative precision (`round(2.15, 1)` is 2.2, `round(-50.55, -2)` is -100). `between` rendered invalid SQL in KSQL; Striem's workaround, which could reorder bound parameters, is removed. Datetime-literal normalization now reaches parse, parse-kv, string-match and temporal nodes.

- Fixed null-input failures: `extract` and `parse-kv` over a null source failed the whole query ("argument must be BLOB or TEXT") because SQLite passes NULL as `[]byte(nil)` to typed UDF parameters; `has` was hardened the same way. `make_set`/`make_list` over an empty or all-null group now return `[]` instead of `null`. `tostring(null)` now returns an empty string as documented, so `strlen`, `countof` and `isempty` over converted nulls match Kusto, and failed `parse` string columns and missing `parse-kv` string keys are empty. A regression test runs over 50 functions with null inputs.

- Added Striem mappings for `pi`, `degrees`, `radians`, `cot`, `exp2`, `exp10`, `log2`, `gamma`, `loggamma`, `erf`, `erfc`, `isfinite`, `isinf`, `isnan`, `max_of`, `min_of`, `strcmp`, `isascii`, `isutf8`, and the aliases `notempty`, `notnull` and `weekofyear`. Microsoft's `log2` and `max_of` examples execute, including null precedence and datetime comparison. `max_of`/`min_of` require one type (with int/long/real widening) and 2–64 arguments. SQLite cannot store NaN or infinity, so nonfinite results are null, and `isnan`/`isinf` can be true only for values that reach the function as NaN or infinity. NULL inputs from SQLite (`[]byte(nil)`) are handled explicitly.

- Added `render` as a validated final annotation in KSQL (`Result.Visualization`) and Striem's query API (`visualization`). Visualizations, per-chart `kind` values, enum, numeric, string and column-list properties, and column existence are checked; rows are unchanged, and a misplaced `render` is rejected. The results header reports the visualization; Striem shows results as a table and does not draw charts. Chart drawing and client-specific axis inference remain open. See KSQL `docs/render-operator.md`.

- Added serialized row-set tracking and window functions in KSQL. `sort`, `top` and `serialize` record order; `where`, `take`, `extend`, the project family and parse operators preserve it unless an ordering column changes. `prev`, `next`, `row_number`, `row_cumsum`, `row_rank_dense` and `row_rank_min`, with restart predicates, lower to SQL windows over a hidden ordinal in `extend`, `project`, `serialize` and `where`. Microsoft's examples for all four row functions execute with documented values. Striem tests cover sign-in gaps and sessionization with datetime differences; the editor, discovery and a Playwright scenario include the functions. A missing string `prev`/`next` value is empty, as KQL strings have no null. `row_window_session`, serialization across `mv-expand` and reassigned ordering columns, and live-engine certification remain open. See KSQL `docs/window-functions.md`.

- Added `parse-kv` through KSQL's `ParseKVSpec` lowering and the pure-Go `runtime.KeyValuesJSON` extractor, registered in Striem as `kql_key_values`. Delimited, free-form and regex modes are covered, along with repeated one- or two-character quotes, escapes, greedy values, first-appearance key selection, typed conversions and in-place replacement. Every Microsoft example executes with its documented values, including datetime and `guid` columns. The new `toguid` mapping accepts 32-digit, hyphenated, braced and parenthesized GUIDs. Option validation, resource limits (1 MiB per value, linear scanning) and fuzzing are tested. Free-mode pairing ambiguities, `_` handling and missing-string empty/null policy remain characterizations; live-engine certification remains open. See KSQL `docs/parse-kv-operator.md`.

- Added `parse` and `parse-where` through KSQL's typed `ParseSpec` lowering and a Striem `kql_regex_captures` UDF that returns one RE2 capture array per row. Simple, regex (with `i`/`m`/`s`/`U` flags) and relaxed kinds, typed columns, strict all-or-nothing conversion, relaxed per-column nulls, user groups inside regex constants and anchored matching are covered. Microsoft's simple, email, regex, regex-flag, relaxed and parse-where examples execute with documented values, as do SQL-like data through the API, aggregation after extraction, schema metadata and positioned diagnostics. A compiler fence (`LIMIT -1 OFFSET 0`) keeps one capture evaluation per row while rows still stream to `take`. The editor, API discovery and a Playwright scenario include both operators. Exact engine regexes for bool/datetime/timespan/guid columns, `parse-kv` and live-engine certification remain open. See KSQL `docs/parse-operator.md` and [Microsoft parse](https://learn.microsoft.com/en-us/kusto/query/parse-operator?view=microsoft-fabric).

- Extended runtime datetime conversion to every example in Microsoft's RFC 822, RFC 850 and Sortable format tables, with optional seconds, a `GMT` zone, weekday consistency checks and a 1969–2068 two-digit-year window. A bounded `M/d/yyyy H:mm[:ss[.fffffff]]` fallback reproduces the parse operator examples; Microsoft does not list it among supported formats. The existing ISO rules are unchanged. Two-digit-year pivots, other zones and .NET-style culture parsing remain uncertified. [Microsoft datetime formats](https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/datetime?view=microsoft-fabric).

## Remaining workstreams (all stay in scope)

1. **Scalar semantics and types:** complete function catalog, Unicode/string behavior, all casts and null-on-failure behavior, dynamic values/literals, GUID/decimal/timespan types, scalar `let`/function definitions, datetime arithmetic, formatting/timezones, Boolean and null semantics.
2. **Aggregates:** full aggregate catalog; `arg_min`/`arg_max` row selection; conditional/dynamic collections; percentiles/statistics; genuine HLL-based approximate counts and mergeable states; ordering/default/empty-input behavior.
3. **Relational operators:** remaining union forms and complete scalar type distinctions, remaining projection forms, parse variants, multi-array expansion, aggregating `mv-apply`, partition/scan, top-nested/top-hitters, series operators, find/search variants, schema operators, and all hints/parameters with their defined semantics.
4. **Ordering and windows:** serialized row identity/order through pipelines; row_number/rank/cumulative/neighbor/session functions and restart predicates.
5. **Sources, statements, and reusable queries:** all source forms; parameter declarations; complete functions/invoke/view semantics; external data; database/cluster/table resolution; entity groups, macro expansion, materialization, session controls.
6. **Graphs and specialized scalar families:** graph construction/matching/path algorithms, geospatial/S2/H3 operations, series analysis, encodings/hashes, network functions, regex compatibility.
7. **Plugins and execution services:** evaluate plugins, their declared output schemas, and any required external runtimes/services. Unavailable services must not be silently replaced with invented results.
8. **Product integration:** completion/highlighting, API contracts, render directives/chart presentation, query diagnostics/cancellation/limits, browser execution, deployment and migration support.
9. **Conformance:** official documented examples, operator composition, differential fixtures against Kusto where available, adversarial/resource cases, platform coverage, current-catalog reconciliation, and a requirement-by-requirement completion audit.

Known existing semantic differences remain open: exact bounded `dcount` differs from Kusto approximation; some SQLite conversions and string indexing differ from KQL; chronology/serialization and dynamic output metadata need broader review. Existing behavior must be corrected as part of full support, rather than declared sufficient.
